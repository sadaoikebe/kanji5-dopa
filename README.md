# 漢字ブースト⑤ 書き取りバトル

小学5年生の漢字193字を、指やペンで実際に書いて敵を倒す1ファイルのブラウザゲーム。書き順まで1画ずつ判定する。
演出は [sadaoikebe/speedometer](https://github.com/sadaoikebe/speedometer) の考え方を借りている
(ワープトンネルの背景シェーダー、3色パレットの循環、画面の縁ゲージ、バネで揺れる針と残像、衝撃波、花火、全画面フラッシュ、モード切替の裏返り)。

`index.html` をブラウザで開くだけで遊べる。通信なし (書き順データは中に埋め込み済み)。記録は localStorage に保存。

## あそびかた (バトル)

- ワープトンネルの奥から敵が迫ってくる。敵は熟語と読みの札を背負っていて、□の漢字が弱点。敵の体力 = その漢字の画数
- 大きな枠に□の漢字を1画ずつ書く。正しい画 (書き順・位置・向き・形がだいたい合う) を書くたびに、枠から敵へ雷が落ちて体力が1減る
- 最後の画で漢字が完成すると必殺の大爆発で敵を倒す。次の敵がすぐ来る
- 判定で弾かれた画は「呪文の暴発」。こちらの体力 (ハート10個) が1減り、敵が少し近づく。弾かれた画は書き直す。同じ画を3回続けてまちがえると、次の画のお手本が薄く出て、光の点が書く向きに走る。「💡ヒント」ボタンでも出せる (1ミス扱い、ダメージはない)
- 敵は時間とともに近づく。到達までの時間は `8 + 2.2 × 画数` 秒 (画数が多い字ほど長い)。1体倒すごとに 0.97 倍ずつ短くなる (最短 0.7 倍)。画面の縁のゲージが残り時間で、少なくなると赤く点滅する
- 敵に到達されると体力が3 (ボスは4) 減り、その字は失敗として記録される。正しい字を書き順どおりに見せてから次の敵へ進む。失敗した字やミスした字は3体後にもう一度出る
- ノーミスで倒すと体力が1回復する。体力が0になるとゲームオーバー。「にげる」でいつでも終われる
- 15画以上の字はボス。大きく、王冠と3つ目の目があり、体力ゲージが派手になる
- 書く速さ (画/分) と COMBO で、トンネルの速さと上の針が上がる。手が止まると2.5秒あたりからトンネルが遅くなる (敵の接近が相対的に速く見える)
- COMBO はノーミスで倒した敵の連続。3 / 6 でギアが上がって色が変わり、10 から金色で得点2倍
- 得点:
  - 1画ダメージごとに 100 × COMBO倍率
  - 撃破で (500 + ボスなら1000 + 速さボーナス最大800 + ノーミスなら300) × COMBO倍率
  - COMBO倍率は 1 + 0.1×COMBO (10以上はさらに2倍)。速さボーナスは「2 + 1.1×画数」秒より速いほど多い
- 結果画面: 倒した敵の数、完成させた字 (ノーミスは金色)、スコア、ランク (S 40000 / A 20000 / B 8000 以上)、ベスト、まちがえた字
- 「苦手だけ特訓」はミスしたことがあって、まだ書き取りマスターしていない字だけで戦う (ベストは更新しない)。マスター = ノーミスで3回以上書けて、ノーミス回数がミス画数の2倍より多い

調整用の定数は `index.html` の「調整用の定数」の段に、判定の許容度は `JUDGE` にある。

## 図鑑

- 倒した漢字は、本人が実際に書いた画の軌跡のまま図鑑に入る。字ごとに最も良い記録を1件だけ残す。ノーミスの記録が優先で、同じ条件なら速いほう
- タイトル (と結果画面) の「📖 図鑑」で開く。収録数を `23/193` のように出す。ノーミスで倒した字には金色の★が付く
- 字をタップすると、本人の書き順どおりに1画ずつ再生する。各画の速さは本人が書いた速さで、0.2〜1.2秒に収める。書き始めの位置に画の番号を出す

## 運筆判定のしくみ

- 書き取りエリアは Pointer Events で1本の指だけを追い、1画ずつ点列を取る (KanjiVG の 109×109 座標に直す)
- お手本の点列は、埋め込んだ SVG パスからブラウザの `getPointAtLength` で取る
- 書いた画とお手本を弧長で33点にリサンプルし、始点・終点のずれ、対応点の平均距離、始点→終点の向き、8区間ごとの進む向き、始点→終点の線からの膨らみ方 (形)、長さを見る。子どもの指書きを前提に甘めにしてある
- 「次に書くべき画」に合っても、ほかの画 (まだ書いていない画、もう書いた画) のほうがはっきり良く合うなら、書き順ちがいとして弾く
- 確定した画から字全体のずれを少しだけ (最大 9) 補正する
- 弾いた理由 (書き順 / 逆向き / 位置 / 形) を画面に出す。うっかりタップはミスに数えない

### 自己検証

判定コードは `index.html` の `◆JUDGE_BEGIN◆`〜`◆JUDGE_END◆` に DOM なしで書いてあり、Node でそのまま実行できる。

```sh
node tools/verify-judge.mjs          # 193字 × (お手本どおり / 入れ替え / 逆向き / ずらし / 形ちがい / 揺らぎ) を検証
PW=/path/to/playwright/index.mjs node tools/browser-test.mjs   # Chromium で getPointAtLength とバトル・図鑑を実際に操作して確認 (任意)
```

最新の結果は `tools/verify-log.txt`。

## 書き順データ (KanjiVG)

書き順データは [KanjiVG](https://kanjivg.tagaini.net/) (© Ulrich Apel and contributors) の
SVG から、193字ぶんの各画の `d` 属性だけを書き順どおりに抜き出して `index.html` に埋め込んでいる。
KanjiVG は [Creative Commons Attribution-Share Alike 3.0 (CC BY-SA 3.0)](https://creativecommons.org/licenses/by-sa/3.0/) で配布されており、
`index.html` に埋め込んだ書き順データ (STROKES_RAW) も同じ CC BY-SA 3.0 に従う。

作り直すとき (取得はビルド時だけ):

```sh
mkdir -p /tmp/kvg
node -e 'const s=require("fs").readFileSync("index.html","utf8").match(/const RAW = `([\s\S]*?)`/)[1];
  for (const l of s.trim().split("\n")) console.log(l.trim().codePointAt(0).toString(16).padStart(5,"0"))' |
  while read h; do curl -fsSL -o /tmp/kvg/$h.svg https://raw.githubusercontent.com/KanjiVG/kanjivg/master/kanji/$h.svg; done
node tools/build-strokes.mjs /tmp/kvg     # index.html の ◆STROKES◆ 区間を書き換える
```

今回の取得元は KanjiVG master `9d7220d` (2026-11-18)。

## 保存データ (localStorage)

### `kanji5dopa.v1` (旧版と同じキー)

旧データは壊さずに読み込む。

- `stats[字]` は `[4択の正解, 4択のミス, ノーミスで書けた回数, 書き取りのミス画数]`。旧版の2要素の配列はそのまま残し、書き取りの記録は3・4番目に足す
- バトルでも意味は変えていない:
  - 敵を倒したとき、ノーミスなら3番目に+1
  - 弾かれた画とヒントは、4番目に1画ずつ足す
  - 敵に到達されて書けなかった字は、4番目にミス1画として足す (苦手だけ特訓に入る)
- マスター判定は書き取りの記録 (3・4番目) だけで行う。苦手だけ特訓には4択でまちがえた字も入る
- ベストスコアはバトル用に `bestB` を新しく持つ。理由は点の付け方がちがうから。`bestW` (書き取り10字固定の点) は終わりなしのバトルの点と比べられず、旧 `best` (4択60秒の点) とも比べられない。どちらも消さずに残す

### `kanji5dopa.zukan.v1` (図鑑)

- 図鑑は大きくなりうるので別キーにした。容量オーバーになっても、成績のほう (`kanji5dopa.v1`) を巻き込まない
- 中身は `{ v:1, z: { 字: rec } }`。`rec` の各項目:
  - `d`: 軌跡。各画を弧長でリサンプルした点列 (長さ3.5ごとに1点、1画2〜24点)。座標は 109 座標系の整数で、1つの値を1文字 (U+00C0 + 値) にして詰める。画は空白で区切る
  - `m`: 画ごとの書いた時間 (10ms 単位)
  - `c`: ノーミスなら 1
  - `s`: 1字にかかった時間 (0.1秒単位)
  - `t`: 保存した時刻
- 容量の目安: 1字あたり平均 約370文字、最大 約430文字。193字すべてで 約7万文字 (UTF-16 で 約140KB)。ブラウザの localStorage (ふつう 5M文字前後) に十分収まる
- 安全策: 図鑑全体が 40万文字 (`Z_BUDGET`) を超えそうなとき、または保存が容量オーバーで失敗したときは、いま保存した字を残したまま、古い通常記録 (ノーミスでない) から順に次の手当てをする:
  - まず点を半分に間引く
  - それでも足りなければ記録ごと消す
  - 通常記録がなくなったら、古いノーミス記録で同じことをする
- 容量オーバー以外の失敗 (localStorage が使えないなど) では間引かない
